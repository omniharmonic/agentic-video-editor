It is kept as a record of intent and is not user documentation; the code, `AGENTS.md`, the skills and the reference docs are authoritative. Paths and names in it describe the first project. See [docs/README.md](../../README.md).

Spec: `docs/superpowers/specs/2026-10-13-agentic-pipeline-design.md`. Read it, `AGENTS.md`, `src/ave/editdoc.py`, `src/ave/state.py`,
`tests/fixtures.py`, `tests/conftest.py` and `src/ave/commands/core.py` before starting. Look at `src/ave/transcribe.py` and `cutplan.py` for house style.

## Charter (applies to every task)

1. **Own only your files.** Create `src/ave/<module>.py` (or package), `src/ave/commands/<module>.py` exposing `register(sub)`, tests
   `tests/test_<module>*.py`, a skill `skills/<name>/SKILL.md`, config under `config/`, docs under `docs/`. **Never edit** `cli.py`,
   `editdoc.py`, `state.py`, `episode.py`, `fixtures.py`, `conftest.py`, `pyproject.toml`, `AGENTS.md`, or another task's files. If you need a
   change there, say so in your final message (and work around it locally); the orchestrator applies it.
2. **Do not run `git commit`/`git add`.** The orchestrator commits. Do not install packages: all extras are already in `.venv`
   (opencv-headless, librosa, playwright+chromium, google-api-python-client, google-auth-oauthlib, requests, keyring, pyyaml, pillow, numpy, scipy, soundfile).
   Use only those plus ffmpeg/ffprobe. Heavy optional deps (torch, open_clip) must be imported lazily with a clear fallback.
3. **Tests first, real behavior.** Use pytest, the synthetic episode (`synth_episode` fixture) for media work, and ffprobe/pixel/loudness
   measurements to verify rendered output. No network in tests (mock HTTP). No private footage. The full suite
   (`.venv/bin/python -m pytest -q`) must pass when you finish, including other tasks' tests; if another task's test fails because that module is
   mid-development, run only yours plus the core tests and say so.
4. **Style:** match `transcribe.py`/`cutplan.py`: small pure functions, docstrings that state WHY, JSON artifacts written atomically via
   `episode.write_json`, errors via `SystemExit("clear message with the fix")` at the CLI edge and exceptions inside libraries. Keep commands
   mechanical and their stdout JSON; editorial judgment belongs in the skill and in policy YAML, never buried in code.
5. **Every automated judgment records `reason` and `confidence`** so a human can audit it.
6. **Skill requirements:** YAML frontmatter `name` (kebab-case, matches the folder) and a `description` stating WHEN to use it. Body: the exact
   commands, how to judge output, failure modes, and checkpoints where the agent must stop for the human. Be concrete and short.
7. **Never destroy**: raw footage is read-only; never overwrite an existing `edits/*.vN.json` (use `editdoc.save_new_version`).
8. **Final message** (this is all the orchestrator sees): what you built, public function signatures, CLI commands, files created,
   test results (counts), real measurements you verified (e.g. loudness, durations), anything you could NOT verify, and requested core changes.

## EditDoc extensions agreed for all tasks

- A dialogue segment may be `{"fill": "room_tone"}` (no source speech): the compiler plays room tone from `tracks.room_tone`.
- Dialogue/video segments carry `reason` and `confidence`. Video segments may carry `crop` `[x,y,w,h]` in **source pixels** (or null) and `zoom` (>=1.0,
  centered punch-in applied after crop). Compilers scale the result to the canvas (letterbox, never distort).
- `captions.ass`/`captions.srt` are paths relative to the episode root.
- Output-time precision is milliseconds; compilers must frame-snap video boundaries to `fps` and keep audio boundaries sample-accurate.

## T1 compile: EditDoc -> media (the FFmpeg engine)

Files: `src/ave/ffutil.py`, `src/ave/compile.py`, `src/ave/presets.py`, `src/ave/commands/render.py`, `tests/test_compile.py`, `skills/ave-render/SKILL.md`.

Public API (other tasks call these):
```python
ffutil.probe(path) -> dict                     # duration, fps, w, h, has_audio, pix_fmt, codec
ffutil.measure_loudness(path) -> {"lufs": float, "true_peak_db": float, "lra": float}   # ebur128
compile.render(ep, doc, out, preset="master", burn_captions=True, overwrite=False) -> dict   # report below
compile.compile_audio(ep, doc, out_wav) -> Path     # the dialogue master (+ music, ducked) as 48 kHz WAV, sample-accurate
compile.compile_video(ep, doc, out_mp4) -> Path     # picture only, canvas size, doc fps
presets.PRESETS: dict                           # master (1080p H.264 CRF 18, -16 LUFS), youtube (-14), proxy (540p fast), audio_only, plus any you justify
```
`render` report: `{ok, out, duration, expected_duration, fps, lufs, true_peak_db, preset, segments, warnings[]}` and it verifies the output with ffprobe
(duration within 1 frame of `doc.duration`, audio and video present, fps correct) and raises if not.

Must support: video segments (source clock = `e0 - start_offset`, crop, zoom, canvas scale with letterbox, fps conform); dialogue segments (gain,
equal-power crossfade `xfade_ms`, `fill: room_tone` with a loop-free fill built from the `room_tone` source range using crossfaded random offsets);
music (gain, fade in/out, trim from `in`, **sidechain ducking** by the dialogue by `duck_db`); overlays (alpha PNG/MOV/image, x/y/w/h, layer order, only visible
between o0 and o1); optional ASS caption burn (`ass` filter; fonts dir from `motion-kit/brand/fonts` if present); two-pass `loudnorm` to the preset target
with true peak <= -1 dBTP. Must scale: a doc with 300 video segments must render correctly (chunk the filter graph or per-segment intermediates; justify your choice).
Write intermediates under `<episode>/work/render/` and clean up partial files on failure. CLI: `ave render <ep> [--stage rough|assembly|final|select:<name>] [--version N] [--preset master] [--out path] [--proxy]`.

Acceptance (tests): render the synthetic assembly doc and assert A (blue) is on screen at t=2 s and B (red) at t=10 s (sample a frame, check dominant color), duration
within 1 frame, loudness within 1 LU of the preset target, true peak <= -1 dB; a crossfaded cut has no click (peak sample delta below a threshold at the seam);
music ducks (music-only segment louder than the same music under dialogue by about `duck_db`); an alpha overlay appears only inside its time window; a 300-segment doc renders.

## T2 cleanup: dead air, fillers, false starts, masked cuts -> rough cut

Files: `src/ave/cleanup.py`, `src/ave/commands/cleanup.py`, `config/cleanup.default.yaml`, `tests/test_cleanup*.py`, `skills/ave-cleanup/SKILL.md`, `docs/cleanup-policy.md`.

CLI: `ave cleanup <ep> [--policy path] [--dry-run] [--from-version N]`, `ave cleanup explain <ep>` (human-readable decisions). Policy resolution: `--policy` > `<ep>/policy/cleanup.yaml` >
`~/.config/ave/cleanup.yaml` > `config/cleanup.default.yaml`; always record the resolved policy inside `work/cleanup.json`.

Pipeline: read `work/transcript.json`, the latest assembly EditDoc, the analysis audio. Detect candidates: dead air (gaps over `pause.max_ms`, shrink toward `pause.target_ms`, floor `pause.floor_ms`),
lexical fillers (um/uh/er; `like`/`you know` flagged review-only), repeated words, short false starts (heuristic; an LLM may add decisions later through a documented
`work/cleanup_overrides.json` that the command honors), optional non-lexical candidates from audio energy inside gaps (flagged, never auto-cut unless policy allows). Protect rules: do not cut a
pause that follows an emotional/laughter/emphasis marker or precedes a punchline (policy-driven heuristics), never cut inside a word, keep a minimum breath/tail, never create a pause
shorter than the floor. Snap every cut to the nearest low-energy valley within +-`snap_ms` and then zero-crossing using the audio. Each cut gets `audio.xfade_ms` by context (intra-speech 5-15, across gap 20-40).
**Mask each cut using video coverage** in this order: speaker change already switches camera -> nothing extra; else switch to the other camera if it covers the moment and `min_hold_s` allows; else a wide
if one exists; else a punch-in (`zoom` 1.10-1.20, alternating) on the segment after the cut; else audio crossfade only and flag `needs_review`. Enforce `min_hold_s`/`max_hold_s` and no same-camera repeat window.
Output: a NEW rough EditDoc version via `editdoc.save_new_version` built with `TimeMap` (dialogue = kept ranges; video = assembly camera choices mapped through the TimeMap, then masks applied) and
`work/cleanup.json` listing every decision `{id, type, e0, e1, action, reason, confidence, mask, review}` plus totals (time removed, fillers cut, dead air shortened). Idempotent: rerunning produces the next version from the same assembly.
Also call `state.set_review(ep, "rough cut ready ...")`.

Acceptance (tests, synthetic episode with known layout in `tests/fixtures.py`): dead air 6-8 s and 16-17 s shortened to the policy target; the "um" at 13.0-13.4 removed; "yeah" kept by default; no cut falls inside a word; rough doc validates and is shorter by the expected amount (+-100 ms); every cut has a mask or a `needs_review` flag; cuts are snapped to low energy (assert on audio); a policy override changes the outcome; running twice makes v1 then v2. Include a test that a camera switch masks a cut when the other camera covers it, and a punch-in when it does not.

## T3 captions: SRT/ASS, styles, burn, re-transcribe

Files: `src/ave/captions.py`, `src/ave/commands/captions.py`, `config/captions.styles.yaml`, `tests/test_captions*.py`, `skills/ave-captions/SKILL.md`.

Public API: `cues_from_edit(ep, doc) -> list[Cue]` (transcript words mapped to OUTPUT time through the doc's dialogue segments; words in removed sections are dropped; words in `fill` segments dropped),
`cues_from_transcript(words, ...)`, `write_srt(cues, path)`, `write_ass(cues, style, canvas, path)`, `burn(video_in, ass, out)`, `check(cues, style) -> list[problem]`,
`retranscribe(ep, video) -> transcript-like dict` (extract 16 kHz mono wav, reuse `ave.transcribe` functions for ASR; diarization optional), `cues_from_words(words)`.
Rules (policy in `config/captions.styles.yaml`, human-tunable, defaults from research): <=42 chars/line and <=2 lines for long-form, <=32 chars for shorts; break at punctuation/pauses/clause boundaries, never leave a one-word orphan line; min cue 0.8 s and max 6 s; reading speed
<=17 chars/s (extend end time within the gap to the next cue if possible); no overlaps; speaker-change starts a new cue; apply `glossary` from `episode.json` (wrong->right) and mark capitalization of proper names given in the glossary. Styles: `podcast` (bottom center, clean, safe margins),
`short` (word-highlight karaoke via ASS `\kf`, centered at ~65% height, bold sans, outline 4-6 px at 1080 wide, safe zone: avoid bottom 25% and 120 px right margin), `minimal`. Positions are computed from canvas size so they stay correct at any resolution (verify at 1920x1080 and 1080x1920).
CLI: `ave captions <ep> [--stage rough|final|select:<name>] [--style podcast|short|minimal] [--burn]` writes `<ep>/captions/<stage>.srt` and `.ass` and records the paths in a NEW EditDoc version (copy of the doc with `captions` set) via `editdoc.save_new_version`;
`ave captions retranscribe <ep> <video> [--srt-out path]` (the exact-match SRT from the rendered final); `ave captions check <ep> <file.srt|ass>`.
Fonts: prefer fonts bundled under `motion-kit/brand/fonts` (may not exist yet; fall back to a macOS system font that exists, e.g. via `fc-match`/Helvetica Neue; never fail because a font is missing, but warn).
Acceptance (tests): synthetic transcript through an EditDoc with a removed section yields correct output-time cues and no cue for removed words; SRT is valid (parse it back); cps/line-length/overlap checks pass for good input and flag bad input; ASS renders through ffmpeg `ass` filter onto a test video and the caption pixels fall inside the safe zone
at both 1920x1080 and 1080x1920 (sample the frame); karaoke style has one `\kf` per word with durations summing to the cue duration; glossary corrections applied.

## T4 clips: find, validate, assemble selects, review pack

Files: `src/ave/clips.py`, `src/ave/commands/clips.py`, `config/clips.rubric.yaml`, `tests/test_clips*.py`, `skills/ave-clip-finder/SKILL.md`, `src/ave/review_pack.py`.

The LLM agent does the judging; code prepares evidence and validates results. CLI:
`ave clips prepare <ep> [--stage rough|final|assembly] [--min-s 20 --max-s 60]` -> `work/clips_candidates.json`: sentences (id `s000`...) with output-time start/end, speaker, text, and per-sentence features, plus candidate windows
(sentence-aligned, within length limits, non-overlapping variants) with cheap features (starts mid-thought? references earlier context via pronouns/"as I said"? filler density, speaker turns, question at start, standalone score hints).
`ave clips propose <ep> --picks picks.json` validates agent picks `[{"title","hook","sentence_ids":["s014".."s031"],"scores":{criterion: 0-10},"rationale"}]` against the rubric in `config/clips.rubric.yaml` (weights from research: hook 25, arc 20, insight 15, emotion 15, shareability 10, ending 10, speech quality 5; penalties for out-of-range length, needs prior context, sensitive); rejects hallucinated ids; snaps
start to the sentence start (trim leading filler), end to sentence end + tail (default 0.3 s); rejects overlaps; computes weighted score; writes `work/clips.json`.
`ave clips build <ep>` -> one `select.<slug>.v1` EditDoc per clip via `editdoc.slice_doc` from the source stage, plus a combined `select.selects.v1` doc concatenating all clips (with a configurable gap) for the "selects timeline"; records `notes` per clip. (Concatenation must produce a valid EditDoc.)
`ave clips review <ep> [--drafts]` -> `exports/review/index.html`: a static contact-sheet page (thumbnails extracted with ffmpeg from the source clip start/mid/end, hook, score breakdown, transcript with the cut handles, rationale, an approve/reject/nudge control that downloads `decisions.json`); with `--drafts` render proxy drafts via `ave.compile` if it exists (import lazily; if not available print a note).
`ave clips decide <ep> decisions.json` records human approve/reject (+nudge by +-N sentences, re-snapping) into `work/clips.json`; approved clips feed shorts. Log every decision (for later rubric tuning) in `work/clips_decisions.jsonl`.
Acceptance (tests on the synthetic episode and a larger synthetic transcript you generate): prepare yields sentence-aligned windows within limits; propose rejects bad ids/overlaps/length; boundaries snap correctly; build produces valid EditDocs whose dialogue maps to the right episode times; the review HTML exists and references real thumbnails; decide applies a nudge.

## T5 publish: approval-gated publishing

Files: `src/ave/publish/{__init__,queue,safety,adapters/{base,youtube,facebook,aggregator}}.py`, `src/ave/commands/publish.py`, `config/platforms.yaml`, `tests/test_publish*.py`, `skills/ave-publish/SKILL.md`, `docs/publishing-setup.md`.

Queue (files under `<ep>/publish/queue/<id>.json`): `{id, video, sha256, platforms:[...], title, description, tags, caption, schedule, visibility, ai_disclosure, status, approvals:[{by,at,sha256}], results:{platform:{...}}}`. Status machine
`draft -> awaiting_approval -> approved -> publishing -> published | failed`, with `rejected`. **Safety invariants (test them):** nothing is sent unless status is approved AND the file's current sha256 equals the approved sha256 (re-encoding after approval invalidates it) AND `--yes` is passed; default is dry-run; publishing is idempotent
(a published item is never re-sent; a crash mid-publish is recoverable and never double-posts); credentials only via OS keychain (`keyring`) or env vars, never written to the repo or logs; logs redact tokens.
Adapters implement `Publisher.preflight(item) -> problems`, `publish(item) -> result`, `status()`. **YouTube**: Data API v3 resumable upload via google-api-python-client, `youtube.upload` scope, OAuth installed-app flow with local server, refresh token in keyring, `publishAt` scheduling, `selfDeclaredMadeForKids`, AI-disclosure field, handle the quota/private-upload outcome and surface it plainly. **Facebook**: Page Reels (`/{page-id}/video_reels` start/upload/finish) and long-form `/videos` with a Page token from keyring/env; scheduling via `scheduled_publish_time`. **Aggregator**: a generic HTTP adapter configured by a YAML file (base URL, auth header name, endpoint templates) so Instagram/X/TikTok can go through a hosted service
(document Ayrshare/Upload-Post/Late as examples, mark as experimental, no hard-coded unverified endpoints). Direct Instagram/X are not implemented; say so in docs.
Preflight uses `config/platforms.yaml` (duration/size/aspect limits; mark each with `verified: true|false` and a source URL; values from the plan research are UNVERIFIED unless noted) and blocks obviously invalid posts (e.g. a 16:9 file for Reels, over-length).
CLI: `ave publish queue <ep> --video f --platforms youtube,facebook --title ... [--from-clips]`, `list`, `show <id>`, `approve <id>` (records who/when/hash), `reject`, `run <id> [--yes] [--dry-run]`, `auth <platform>`, `status`. Never call `run` implicitly from other commands.
Acceptance (tests, HTTP mocked): invariants above; approval invalidated by changing the file; dry-run default; idempotency across a simulated crash; preflight blocks bad aspect/length; YouTube resumable upload flow against a mocked service; Facebook reel three-step flow against mocks; token redaction. Document the exact one-time manual setup per platform in `docs/publishing-setup.md` (from the research: YouTube Cloud project + Production consent + Desktop client, audit form if uploads stay private; Meta app + Business Verification + permissions + app review; X developer credits; TikTok audit).

## T8 shorts: vertical reframing, short EditDocs, per-platform exports (wave 2)

Files: `src/ave/reframe.py`, `src/ave/shorts.py`, `src/ave/commands/shorts.py`, `config/shorts.yaml`, `tests/test_shorts*.py`, `skills/ave-shorts/SKILL.md`. You MAY add keys to `src/ave/presets.py` (T1 is finished; keep its style and tests green) for the platform presets.

Read their skills and public APIs first (T1 `skills/ave-render`, T3 `skills/ave-captions`, T4 `skills/ave-clip-finder`).

Reframing (`reframe.py`): face detection on Apple Silicon via **Apple Vision** (`pyobjc-framework-Vision` is installed: `VNDetectFaceRectanglesRequest` on frames extracted with ffmpeg; OpenCV 5 here has NO Haar cascades). Sample frames across each camera segment, take the median face box, compute a 9:16 crop rectangle in SOURCE PIXELS (face centered horizontally, headroom ~ upper third, never outside the frame, even width/height) and a `zoom`. MVP = one static crop per segment (no panning, no jitter); if no face is found fall back to a center crop and flag `needs_review`. For a segment where the speaker is NOT the camera's subject (reaction), still crop that camera's face. Optional layout `stack` (two speakers top/bottom 1080x960 each) only if you can do it cleanly with EditDoc overlays/crops; otherwise document it as future work. Provide a debug still (`ave shorts preview`) that draws the crop rectangle and safe zone on a frame so the agent can LOOK.
Shorts (`shorts.py`): from an approved clip (`select.<slug>` doc) build a `short` EditDoc named `<slug>` (canvas 1080x1920, fps from source, 30 recommended) via `editdoc.save_new_version(ep, doc, name=slug)`: crop per video segment from reframe, speaker-change cuts preserved with `min_hold` so a 25-60 s clip is not a blur of cuts, captions generated with the `short` style (`ave.captions.make_captions`/`write_ass`) and attached, optional music/overlays left untouched if present. Export presets per platform in `config/shorts.yaml` and `presets.py`: YouTube Shorts / Reels / Facebook Reels / X, all H.264 High 1080x1920 yuv420p BT.709 faststart, AAC 192k, loudness -14 LUFS TP <= -1.5 (compile already keeps true peak safe); X gets a size/duration check. Every export also writes a sidecar `<name>.json` (title, hook, description draft from `clips.json`, platform limits check, license coverage via `ave.assets.licenses` if music/b-roll used) that `ave publish queue --from-clips` can use (look at `src/ave/publish/queue.py` to match what it reads).
CLI: `ave shorts build <ep> [--clip slug|--all-approved] [--layout crop|stack]`, `ave shorts preview <ep> <slug> [--t S]`, `ave shorts export <ep> [--clip slug|--all] [--platforms youtube,reels,...]` (renders via `compile.render`, verifies with ffprobe, writes sidecars under `exports/shorts/`), `ave shorts list <ep>`. Idempotent and versioned (never overwrite). `ave status` treats `exports/shorts/*.mp4` as the shorts stage done.
Acceptance (tests on the synthetic episode, plus use REAL footage only for local face-detection validation): the synthetic episode has solid-color cameras with no faces, so test fallback + flagging; for the Apple Vision path, generate a test image with a drawn face-like pattern is unreliable, so ALSO validate on a real frame from `<scratch>/multicam-smoke/raw/camA.mov` (extract a frame with ffmpeg at 300 s; it contains one person) and LOOK at the crop preview with the Read tool; make that real-footage test skip cleanly when the file is absent. Tests: crop geometry invariants (inside frame, 9:16, even dims), short doc validates and has canvas 1080x1920, render output is 1080x1920 with correct duration, loudness within 1 LU of -14, captions inside the safe zone in the rendered frame, sidecar contents, versioning.

## T9 layout + session protocol (wave 3, runs ALONE: it refactors shared modules)
